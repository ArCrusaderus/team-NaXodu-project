# Матрица RACI: Работа с репозиторием проекта

| Задача | Руководитель разработки (Панченко А.) | Программист (Папазян Е.) | Архитектор ПО (Наврузбеков А.) | Специалист по данным (Орлов Т.) | Специалист по тестированию (Подъяпольский И.) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Создание и настройка репозитория | **A** | I | **R** | I | I |
| Поддержание структуры папок и файлов | **A** | **R** | **R** | **R** | **R** |
| Написание отчётов по практическим работам | **A** | **R** | **R** | **R** | **R** |
| Внесение коммитов с осмысленными сообщениями | **A** | **R** | **R** | **R** | **R** |
| Проверка Pull Request (Code Review) | **A** | C | **R** | I | I |
| Слияние веток (Merge) | **A/R** | I | I | I | I |
| Резервное копирование и актуальность репозитория | **A** | **R** | **R** | **R** | **R** |

## Легенда
-   **R (Responsible)** — исполнитель задачи.
-   **A (Accountable)** — ответственный за результат (утверждает работу).
-   **C (Consulted)** — консультируемый участник (предоставляет информацию до выполнения).
-   **I (Informed)** — информируемый участник (уведомляется после выполнения).

## Пояснения к распределению
1.  **Создание репозитория:** Ответственность (A) лежит на руководителе как организаторе процесса. Исполнитель (R) — архитектор ПО, так как эта роль предполагает ответственность за инфраструктуру и техническую организацию рабочего пространства согласно методичке.
2.  **Проверка Pull Request:** Архитектор ПО выступает основным проверяющим (R), так как оценивает соответствие изменений технической структуре проекта. Руководитель несёт итоговую ответственность (A) за качество кодовой базы.
3.  **Слияние веток:** Выполняется исключительно руководителем разработки (R/A) для сохранения стабильности основной ветки `main`.
4.  **Поддержание структуры и отчёты:** Все участники (R) отвечают за свои разделы и файлы в соответствии с назначенными ролями. Руководитель контролирует соблюдение единых стандартов оформления (A).
